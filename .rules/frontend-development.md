# 前端开发规则

## CSS 开发规范

### ⚠️ 禁止事项（重要教训）

#### 1. 禁止重复或不完整的样式定义

**问题案例**（已发生过）：
```css
/* 原有的完整定义 */
.topic-card-remove {
    cursor: pointer;
    color: #e74c3c;
    /* ... */
}

/* 新添加样式时的误操作 */
.topic-card-dropdown-btn {
    /* ... */
}

.dropdown-menu-item {
    /* ... */
}

.dropdown-menu-item:hover {
    background: #4ecdc4;
    color: #1a1a1a;
}

.topic-card-remove {                    /* ❌ 错误：重复定义且不完整 */
                                     /* 只有 { 没有 }，导致后续所有样式失效 */
.stocks-drop-zone {                    /* 从这里开始的所有样式都无法被解析 */
    min-height: 100px;
    /* ... */
}
```

**后果**：
- 从不完整定义开始的所有CSS样式（可能数千行）都将无法被解析
- 整个页面的样式完全混乱，难以排查原因
- 控制台可能没有明确的错误提示

**正确做法**：
```css
/* 原有的完整定义 */
.topic-card-remove {
    cursor: pointer;
    color: #e74c3c;
    /* ... */
}

/* 新添加样式 */
.topic-card-dropdown-btn {
    /* ... */
}

.dropdown-menu-item {
    /* ... */
}

.dropdown-menu-item:hover {
    background: #4ecdc4;
    color: #1a1a1a;
}

/* 不要重复定义已有的类名 */
```

**检查方法**：
1. 使用编辑器的搜索功能，查找是否已存在相同的类名定义
2. 在添加新样式前，先搜索整个文件的 `\.类名\s*{` 模式
3. 确保每个样式定义都有完整的 `{ ... }` 配对
4. 使用 CSS 验证工具或 linter（如 Stylelint）

#### 2. 新增样式时的最佳实践

1. **搜索现有定义**：在添加新样式前，先搜索是否已有相同或相似的类名
2. **检查定义位置**：将样式添加到合适的位置，保持文件结构清晰
3. **使用有意义的命名**：避免过于通用的类名（如 `.item`、`.btn`），使用具体前缀（如 `.topic-card-`、`.help-modal-`）
4. **考虑样式复用**：如果多个组件需要相同样式，考虑提取为通用样式类
5. **注释说明**：为复杂的样式选择器添加注释，说明用途

### 代码检查清单

在提交前端代码（尤其是CSS/HTML修改）前，必须检查：

- [ ] 搜索整个文件中是否有重复的CSS类名定义
- [ ] 确保每个新的样式定义都有完整的 `{` 和 `}`
- [ ] 测试所有受影响的页面和组件
- [ ] 检查浏览器控制台是否有CSS相关的警告或错误
- [ ] 验证新增功能在不同屏幕尺寸下的表现
- [ ] 确认没有破坏现有功能的样式

### 调试技巧

遇到样式问题时：

1. **优先检查控制台**：使用 F12 打开开发者工具，查看 Console 标签是否有错误
2. **检查元素样式**：在 Elements 标签中选中问题元素，查看 Computed 样式是否正确应用
3. **检查样式冲突**：查看某个样式是否被其他选择器覆盖
4. **检查文件结构**：使用文本编辑器的括号匹配功能，检查是否有不闭合的样式定义
5. **逐步恢复**：如果问题严重，可以回退到上一个可用的版本，然后逐个添加修改

### 常见错误

1. **复制粘贴时的重复定义**：从其他文件复制样式时，忘记检查类名是否已存在
2. **样式定义不闭合**：编辑时误删了闭合的 `}`
3. **CSS注释格式错误**：使用 `/* */` 注释时忘记闭合
4. **选择器优先级问题**：样式被高优先级的选择器覆盖，需要使用 `!important` 或提高选择器优先级

## HTML/CSS 最佳实践

### 1. 样式组织

- 相关样式放在一起，使用注释分隔不同区域
- 按组件或功能模块组织样式
- 公共样式放在文件顶部，具体组件样式放在后面

### 2. 选择器使用

- 避免过度嵌套（一般不超过3层）
- 优先使用类选择器，避免过度使用ID选择器
- 使用具体的类名，避免通用选择器（如 `*`）

### 3. 响应式设计

- 使用相对单位（`rem`, `%`, `vh`, `vw`）而非固定像素（`px`）
- 考虑移动端和不同屏幕尺寸的适配
- 使用媒体查询处理不同断点的样式

### 4. 性能优化

- 避免不必要的复杂选择器
- 减少使用昂贵的伪类（如 `:nth-child` 在大量元素上）
- 减少重排和重绘（使用 transform 和 opacity 代替 top/left/opacity）
